# Autoban — план

Android-приложение: автосброс и автобан входящих звонков по настраиваемым правилам, журнал, уведомления в Telegram.

## Исходные требования

| # | Правило | Условия | Действие |
|---|---|---|---|
| 1 | Скрытые на SIM1 | SIM1 **и** номер скрыт/не определён | Сброс |
| 2 | Маркированные на SIM2 | SIM2 **и** система показывает имя абонента, совпадающее с маской (пример: «Ростелеком») | Сброс + номер в бан |

- Забаненный номер сбрасывается дальше на любой SIM.
- Пока только сброс (без скрытия из журнала вызовов/уведомлений) — опции заложены, но выключены.
- Целевое устройство: Samsung Galaxy Note 9, **Android 10 (API 29)** — подтверждено. Плюс поддержка свежих Android (до 16+). Запасной путь для API 26–28 на Note 9 не нужен.
- Прежний определитель (Truecaller) удалён — роль «Фильтр звонков» свободна.

## 1. Механизм

**Основной путь (Android 10+, API 29+): `CallScreeningService` + роль `ROLE_CALL_SCREENING`.**
Система сама будит сервис на каждый входящий не из контактов; фоновый процесс не нужен, батарейные оптимизации Samsung/Xiaomi не мешают. На ответ ~5 секунд → решение принимается локально, всё медленное (Telegram) — асинхронно после ответа.

Данные из `Call.Details`:

| Что | Откуда |
|---|---|
| SIM | `getAccountHandle()` → subId. API 30+: `TelephonyManager.getSubscriptionId(handle)`. API 29 (Note 9): `PhoneAccountHandle.getId()` (у Samsung это subId или ICCID) → сопоставление через `SubscriptionManager.getActiveSubscriptionInfoList()`; запасной вариант — порядок `TelecomManager.getCallCapablePhoneAccounts()` + метка аккаунта. Какой способ работает — выясняет этап 0. |
| Номер скрыт | `getHandlePresentation()` ∈ `RESTRICTED`/`UNKNOWN`/`PAYPHONE` или `getHandle() == null` |
| Номер | `getHandle()`, нормализация в E.164 (libphonenumber): `8912…` → `+7912…` |
| Имя от сети | `getCallerDisplayName()` + `getCallerDisplayNamePresentation()` (CNAP / маркировка оператора) |

Ответ: `CallResponse` с `setDisallowCall(true) + setRejectCall(true)`.

**Запасной путь (если Note 9 окажется на Android 8/9, API 26–28):** роли нет, а `CallScreeningService` там работает только у звонилки по умолчанию. Тогда — `BroadcastReceiver` на `PHONE_STATE` + `TelecomManager.endCall()` (API 28, `ANSWER_PHONE_CALLS`) / `ITelephony` через reflection (API 26–27); SIM — из Samsung-extras интента (`subscription`/`slot`). Делается только если понадобится. `minSdk = 26`, `targetSdk` = актуальный.

### ⚠️ Главный риск: откуда берётся «Ростелеком»

Надпись может приходить из трёх мест, и приложение видит только первое:
1. **Сеть** (CNAP / маркировка звонков оператором) → `getCallerDisplayName()` — ✅ видим.
2. **GetContact** (своя плашка поверх звонка) — ❌ не видим.
3. **Samsung Smart Call** (Hiya, встроенный определитель) — ❌ не видим.

Этап 0 отвечает на это: при выключенном GetContact логгер покажет, есть ли имя в `Call.Details`. Если имени нет — правило 2 строим на масках номеров (диапазоны, префиксы), а условие «имя» остаётся для сетей, где оно передаётся.

## 2. Движок правил (чистый Kotlin, без Android → покрыт unit-тестами)

```kotlin
Rule(
  id, name, enabled, priority,
  mode: ACTIVE | DRY_RUN,          // DRY_RUN — только пишет в журнал «сработало бы»
  conditions: List<Condition>,     // все условия должны выполниться (И)
  action: ALLOW | REJECT | BAN,    // BAN = REJECT + номер в бан-лист
  options: notifyTelegram, skipCallLog=false, skipNotification=false
)
```

Условия:
- `Sim(subId, slotFallback)` — привязка к SIM по subId, чтобы перестановка карт не ломала правило
- `NumberHidden` / `NumberPresented`
- `CallerName(mask)` — **маска по имени**: `*`, `?`, регистр не важен, `ё=е`; опционально regex. Пример: `*ростелеком*`. Пустая маска `*` = «любое имя показано»
- `NumberMask(mask)` — `+7495*`, `+7800???????`, `8800*` (сравнение по нормализованному номеру)
- `TimeWindow(дни, часы)`
- `RepeatedCall(n, minutes)` — исключение «звонят повторно → видимо, срочно»

Бан-лист и белый список хранят и точные номера, и маски.

Порядок проверки: **белый список → бан-лист → правила по приоритету → по умолчанию пропустить**. Срабатывает первое подходящее.

## 3. Журнал

Room, таблица `call_events`: время, номер (сырой/нормализованный), presentation, SIM (слот, subId, имя оператора SIM), имя от сети, сработавшее правило, действие, dry-run, статус отправки в Telegram, «сырые» поля `Call.Details` (для отладки).

Экраны:
- **Журнал** — лента, фильтры (действие / SIM / дата), поиск по номеру, цветовые метки.
- **Карточка события** — «Разбанить», «В белый список», «Создать правило по этому звонку», «Скопировать номер».
- **Бан-лист / белый список** — когда и каким правилом добавлено.
- **Статистика** — день/неделя, по SIM и правилам.
- Экспорт CSV/JSON, срок хранения (по умолчанию 90 дней).

## 4. Telegram

- Настройка: токен бота (@BotFather) + `chat_id`, кнопка «Тест». Токен — в зашифрованном хранилище (Android Keystore).
- Доставка: событие → Room → WorkManager (ждёт сеть, повторы с backoff) → `sendMessage`. Без сети ничего не теряется.
- Прокси (SOCKS5/HTTP) — на случай проблем с доступом к `api.telegram.org`.
- Режим «сразу» или «сводка раз в N минут».

```
🚫 БАН · SIM2
+7 912 345-67-89 · «Ростелеком»
Правило: «Маркированные на SIM2»
24.11.2026 14:32
```

Позже (опционально): inline-кнопки «Разбанить» / «В белый список», команды `/last`, `/stats`, `/ban`. Требует опроса `getUpdates` с телефона — реакция с задержкой до нескольких минут.

## 5. Защита от потери важных звонков

- Новые правила создаются в **DRY_RUN**; включаем после просмотра журнала.
- Белый список проверяется первым.
- Исключение для повторного звонка в течение N минут.
- Тестер правил: ввести вымышленный звонок (SIM, номер, скрыт/нет, имя) → увидеть, что сработает.
- Сброшенные звонки остаются в системном журнале вызовов.

## 6. Стек и структура

Kotlin, Jetpack Compose (Material 3), Room, DataStore, WorkManager, OkHttp, libphonenumber, Gradle (Kotlin DSL, version catalog). Разрешения: `READ_PHONE_STATE`, `INTERNET`, `POST_NOTIFICATIONS`; на API 26–28 дополнительно `ANSWER_PHONE_CALLS`. Распространение — APK напрямую, без Google Play.

### Решения по ходу работы

- **SIM.** Фильтру звонков система не передаёт `accountHandle` (на эмуляторе API 37 он `null`; скорее всего, на Android 10 тоже). SIM определяется по тому, какая подписка сейчас в состоянии RINGING: API 31+ — `getCallStateForSubscription()`, API 29–30 — `PhoneStateListener` на каждую подписку (первый вызов приходит сразу с текущим состоянием). Способ пишется в журнал («via ringing / handle / single»).
- **БД.** Обычный SQLite (`SQLiteOpenHelper`) вместо Room: KSP с встроенным Kotlin в AGP 9 — лишний риск, а таблиц всего три.
- **Номера.** Своя нормализация для РФ вместо libphonenumber: маска сравнивается с вариантами `+7…`, `7…`, `8…`.
- **Условие SIM** — по слоту (1/2), а не по subId: проще в UI, перестановка карт — редкость.
- **Правило 2** предустановлено как `SIM2 и номер передан и имя ~ «*ростелеком*» → бан`; маску можно сменить (например, на `*` = «любое имя от сети»).
- **HTTP** — `HttpURLConnection` (поддерживает прокси), без OkHttp.

6. Telegram: написать боту → Настройки → токен → «Найти» → включить → Сохранить → «Тест».
